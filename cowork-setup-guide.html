Part 0

The Discovery Process

Before you fill in a single template, you need to have the right conversations with Claude. The quality of your system depends entirely on the quality of information you put into it.

For each section below, there's a ready-to-paste prompt you can copy straight into your CoWork chat. Claude will interview you and ask the right questions. You don't have to think of what to say, just answer what Claude asks.

Why this matters

Every section in this guide was born from conversations like these. The people.md file exists because knowing who "Nancy" is saves 30 seconds of context every session. The food-preferences.md exists because a picky eater got generic restaurant recommendations one too many times. You don't need everything perfect on day one. The system has a built-in correction loop.

CLAUDE.md — The Master Memory File

This is the single most important file in your system. It lives at the root of your workspace and Claude reads it automatically at the start of every session. It's the instruction manual for your life.

Rule

Keep it under ~150 lines. Detailed info goes in memory files. CLAUDE.md is the index, not the encyclopedia.

Rule

Link, don't duplicate. Instead of listing every food preference, say "See memory/food-preferences.md."

Rule

Update regularly. Every weekly review should include a CLAUDE.md refresh.

Part 3

Memory Files

Memory files are the deep-context layer. CLAUDE.md points to them, but the details live here. Claude reads only the relevant ones based on what you're asking it to do.

Without memory files, Claude re-learns your preferences every session. With them, it already knows that "Nancy" is your boss, that you hate cottage cheese, and that you sign casual emails with "xx."

Real writing samples beat descriptions. One real email teaches Claude more than a paragraph of adjectives.

Folder Structure (PARA)

PARA stands for Projects, Areas, Resources, Archive. It's the organizational backbone. Everything has a home.

Folder structure
00-inbox/          → Drop zone. Unsorted captures, raw ideas.
01-projects/       → Active projects with goals and end dates.
   [project-name]/ → One folder per project.
02-areas/          → Ongoing life areas. No end date. (Career, health, etc.)
   [area-name]/    → One folder per area.
03-resources/      → Reference material. Templates, skills, research.
   skills/         → Custom Claude skills (see Part 5).
   templates/      → Reusable templates for common outputs.
   skill-feedback/ → Logs of what worked per skill.
04-archive/        → Done or dormant. Nothing gets deleted.
05-automations/    → Automation configs and logs.
   logs/           → Output logs from scheduled tasks.
memory/            → Deep context files Claude reads.

Part 5

Custom Skills

Skills are pre-built workflows that tell Claude exactly how to handle your most common tasks. They live in 03-resources/skills/[skill-name]/SKILL.md.

Without a skill, Claude handles every task from scratch. With a skill, it knows the exact steps, the right tone, which memory files to read, what format to use, and what mistakes to avoid.

Anatomy of a Skill File

Required Frontmatter — name + description with trigger phrases and "do NOT use for" conditions
Required Context — why this skill exists and what problem it solves
Important Pre-flight questions — what Claude should ask before diving in
Required Execution steps — the step-by-step process
Required Output format — exact template for the output
Important Key references — which memory files to read
Important Self-improvement loop — how the skill learns from corrections
Optional Common mistakes — specific anti-patterns to avoid
Optional Example — sample input/output showing the skill in action

Skills Everyone Should Consider

Communication

Email Drafter

Writes emails in your voice. Reads writing-voice.md and people.md. Different templates for boss, colleague, friend, cold outreach.

Productivity

Inbox Triage

Scans email, prioritizes by tiers (needs response, FYI, skip). Offers to draft quick responses. Speed over perfection.

Research

Research Brief

Deep research on a topic, company, or person. Structured output with findings, implications, and next steps.

Planning

Trip Planner

Full trip plans respecting your specific preferences — airline status, dietary needs, fitness routine, budget.

Review

Weekly Review

End-of-week recap: what got done, what's stalled, memory file refresh, system health check, next week priorities.

Career

Interview Prep

Company-specific cheat sheet (60-second pitch, STAR stories, questions to ask, landmines) + mock Q&A practice.

The Self-Improvement Loop

Don't skip this

Every skill should have a feedback mechanism. Before running: check the skill-feedback file for past corrections. After running: collect feedback. When corrected: (a) fix the output, (b) log the feedback with date, (c) if there's a pattern, propose an update to the SKILL.md itself.

This means your skills get better every time something goes wrong. After a few weeks, mediocre skills become excellent ones.

Composable Skill Chains

Skills can be chained for multi-step workflows. Define these in CLAUDE.md:

  • Research → Email: Research a company, then draft outreach referencing specific findings
  • Triage → Draft: Scan inbox, identify emails needing responses, draft replies
  • Research → Interview Prep: Research, then generate cheat sheet + mock Q&A

Part 6

Scheduled Tasks

Scheduled tasks are Claude sessions that run automatically on a schedule. They do work while you're away so things are ready when you sit down.

Important constraint

Scheduled tasks only run when your computer is awake and Claude Desktop is open. If your laptop is closed, the task misses its window. Build a habit of leaving Claude open.

Paste this into CoWork
Let's set up my scheduled automations. Before creating anything, ask me: 1. What time do I usually wake up / start my day? 2. When do I typically sit down to use Claude? (Morning, evening, weekends?) 3. Do I have email connected? (Gmail / Google Workspace) 4. Do I have a calendar connected? 5. What would be most useful to have done FOR me automatically — email summary, calendar prep, weekly review, industry news, something else? 6. Are there any recurring tasks I do on a schedule that could be automated? Based on my answers, recommend 2-3 scheduled tasks to start with (don't overwhelm me). For each one, explain what it will do and when it will run. Get my approval, then set them up. Important: Remind me that my laptop needs to be awake and Claude Desktop needs to be open for these to run. Ask me about anything else in my routine or workflow that could benefit from automation — I might not think of everything on my own.

Automations to Consider

Daily

Morning Briefing

Email summary, today's calendar with per-meeting context, priorities, relevant news. Weekdays, 30-60 min before you start work.

Weekly

Weekly Review

What got done, what's stalled, project status, memory file refresh, system health check, next week priorities. Friday or Sunday.

Daily

Inbox Digest

Prioritized email summary timed for when you usually sit down with Claude. Batch-process responses.

Weekly

Industry Tracker

News, job postings, company updates in your target area. Weekly on whatever day makes sense for your rhythm.

Tips for Reliable Automations

  • Be specific in the prompt. Don't just say "check my email." Say exactly what to scan, how to prioritize, what format, and where to save output.
  • Include file paths. Tell the automation where to save results.
  • Reference skills. Tell the automation to follow a specific skill for format and tone.
  • Build in verification. Cross-check against a known source of truth rather than guessing.
  • Check outputs for the first few days. Automations need tuning. Review and correct early.

Dispatch

Pair your phone to CoWork via Dispatch (QR code). Send tasks anytime. They'll be waiting when Claude runs. Same "laptop must be awake" constraint.

The Corrections Loop

This is the single most important maintenance mechanism. Every time Claude makes a mistake:

Step 1 Fix the mistake immediately
Step 2 Log it in CLAUDE.md under Corrections & Learnings with the date
Step 3 Check if it reveals new info — update the relevant memory file
Step 4 Check if it reveals a skill gap — propose an update to the SKILL.md

Lessons Learned

What Actually Matters

After months of iteration, these are the lessons that made the biggest difference.

Lesson 01

Real writing samples beat descriptions

You can describe your voice all day. One real email teaches Claude more than a paragraph of adjectives. Share actual messages across different contexts.

Lesson 02

Negative instructions are as important as positive ones

"Never use these words" is just as valuable as "use this tone." The anti-pattern list prevents the most common AI cringe.

Lesson 03

The correction loop is the secret weapon

Systems that learn from mistakes get exponentially better. Systems that don't stay mediocre forever.

Lesson 04

Discovery before building

Sessions spent just talking, before any file was created, produced the best material. You can't build a system for someone you don't know.

Lesson 05

Skills need boundaries

"Do NOT use this skill for" is as important as the trigger. Without it, skills fire on the wrong tasks and produce bad output.

Lesson 06

Less is more in CLAUDE.md

Keep the master file lean (~150 lines) and link to memory files. A 300-line CLAUDE.md is harder for Claude to parse than a 100-line one with good links.

Lesson 07

Start with one pain point

Don't build everything at once. Pick your biggest pain point and build the skill for that first. Expand from there.

Lesson 08

Automations need babysitting at first

Check outputs for the first week. Tweak the prompts. They stabilize after a few iterations.

Lesson 09

Specific beats comprehensive

"Picky eater, loves seafood, hates most cheese" is more useful than a generic dietary questionnaire. Specificity wins.

Lesson 10

If maintaining it feels like work, something is wrong

The system should work for you, not create more work. Reduce friction until it's effortless. If you're avoiding it, redesign it.
